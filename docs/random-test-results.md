### RE 発生パターンと原因分類

| 原因 | 該当問題 | 対応方針 |
|------|----------|---------|
| **文字列制約スキップ後の型不一致** | abc441/b, abc450/e | `からなる` なし文字列の検出強化 |
| **N×N 行列（N が大きすぎる）** | abc445/f | 2D 配列で次元が大きい場合に上限を絞るヒューリスティック |
| **3D 配列** | abc440/g | 3D 配列生成は未対応 |
| **配列長に式** | abc453/b | `(t)+1` 等の式評価（`parse_n_repeat` の改善） |
| **クエリ型分岐（match 形式）** | abc441/g | TypedRepeat と構造が異なり未対応 |
| **その他・要調査** | abc441/c, abc450/b | 要調査 |

### HANG パターン（AllMax OOM）

abc443/e, abc445/e: N,K≤10^8 の制約で AllMax ケースが解プロセスを OOM/SIGKILL させる。
入力生成自体は成功するが、解の実行がフリーズ/クラッシュする。
